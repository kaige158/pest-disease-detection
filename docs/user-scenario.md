# 用户场景设计文档

> 版本: v4.0 | 日期: 2026-08-08 | 阶段: 1.6 真实交付场景重构
> 原则: 每个功能都要对应一个真实用户场景

---

## 一、四种用户角色定义

```
平台管理员 (老师本人)
    │
    ├──→ 系统配置、用户管理、最高权限
    │
农业专家 (老师 + 同事/合作专家)
    │
    ├──→ 知识生产者: 录入/编辑病虫害知识
    ├──→ AI审核者: 审核修正AI识别结果
    ├──→ 数据管理者: 查看统计、导出数据
    └──→ 内容维护者: 管理多语言翻译
    │
农业技术推广人员 (老挝当地技术员)
    │
    ├──→ 田野采集: 田间拍照 + GPS + 环境记录
    ├──→ 农户培训: 教农户使用APP
    └──→ 数据上报: 批量上传采集数据
    │
农户/种植户 (老挝农民)
    │
    ├──→ 拍照诊断: 遇到问题拍照识别
    ├──→ 查看方案: 看防治建议
    ├──→ 反馈结果: 确认/质疑AI结果
    └──→ 学习知识: 浏览知识库
```

   │                                │

   │ (白菜黑斑病)                    │
   │ ຄວາມໝັ້ນໃຈ: 89%               │
   │                                │
   │ 📋 ວິທີປ້ອງກັນ:               │
   │ • ຢາ: 50% 多菌灵 500倍液       │
   │ • ສີດທຸກໆ 7 ມື້              │
   │ • ເກັບໃບທີ່ເປັນພະຍາດທຳລາຍ  │

## 三、场景2: 技术员田野采集

### 故事

> 老挝农业部的一位技术推广人员，每周下乡巡田。他用APP连续拍照采集病虫害样本，自动记录GPS和作物信息，晚上回到办公室批量上传。

### 完整交互流程

```
1. 登录APP → 切换到"采集模式"(技术员专属)
2. 选择当前农田信息: [白菜] [生长期: 结球期] [万象省]
3. 开始巡田:
   ├── 发现异常 → 拍照(自动标记GPS)
   ├── 继续巡田 → 再拍照
   └── 连续拍完20张
4. 批量提交 → 每张图自动关联:
   ├── 作物: 白菜
   ├── 生长期: 结球期
   ├── GPS坐标
   ├── 拍摄时间
   └── 天气信息(自动查询)
5. AI批量预标注 → 技术员快速确认/修正
6. 全部上传到服务器

数据价值:
- 20张图片 × 完整元数据 = 高质量训练样本
- GPS轨迹 = 病虫害地理分布数据
- 生长期标注 = 发病规律研究数据
```

## 四、场景3: 老师审核AI结果

### 故事

> 老师每周一登录专家后台，查看本周新增的待审核识别结果。她逐条查看AI判断是否正确，修正错误的，确认正确的。这个过程每周只需30分钟。

### 完整交互流程

```
1. 登录Web专家后台
2. 首页看板显示:
   ┌──────────────────────────────────┐
   │ 待审核: 23条 | 本周新增: 127条    │
   │ AI准确率(本月): 87%              │
   │ 数据总量: 1,247张                │
   └──────────────────────────────────┘
3. 点击"AI审核中心" → 进入审核列表
4. 逐条审核:
   ┌──────────────────────────────────┐
   │ [图片]  🤖 AI: 番茄晚疫病 92%    │
   │         地区: 万象 | 时间: 08-07 │
   │                                  │
   │ ○ AI正确  ○ AI错误              │
   │ 修正: [选择正确病虫害 ▼]         │
   │ 备注: [_______________]          │
   │ [确认] [跳过] [废弃]             │
   └──────────────────────────────────┘
5. 老师快速审核23条(约15分钟):
   ├── 18条AI正确 → 直接确认
   ├── 3条AI错误 → 修正标注(~30秒/条)
   └── 2条图片模糊 → 标记废弃

6. 审核结果自动:
   ├── 确认的图片 → 标记 expert_verified → 纳入训练数据集
   ├── 修正的图片 → 标记 expert_corrected → AI标注被覆盖
   └── 废弃的图片 → 标记 rejected → 不影响统计数据
```

## 七、场景6: 农户反馈形成闭环

### 故事

> 农户识别结果下方有"正确/不正确"按钮。当足够多农户标记"不正确"时，该结果自动进入专家复核队列。

### 反馈闭环

```
用户确认/质疑
    │
    ├──→ ✅ 用户确认 → 提升该结果权重 → 作为正样本
    │
    └──→ ❌ 用户质疑
            │
            └──→ 累计3人质疑 → 自动进入专家审核队列
                    │
                    └──→ 专家复查 → 修正/确认
                            │
                            └──→ 数据回流 → 更新知识库
```

# 生产部署手册

> 更新日期：2026-09-26
> 适用：把平台部署到云服务器（或学校服务器）并交接运营

---

## 一、部署前必须理解的三个密钥

平台有三个密钥**必须正确配置**，配错的后果很严重：

| 变量 | 作用 | 配错的后果 |
|------|------|-----------|
| `JWT_SECRET` | 签发登录令牌 | 用弱值或默认值 → **任何人都能伪造任意用户的登录令牌** |
| `AI_KEY_SECRET` | 加密数据库里的 AI API Key | 未配置 → 用开发密钥，换机器后密文解不开；**一旦设定不可更改** |
| `ADMIN_INIT_PASSWORD` | 管理员初始密码 | 留空 → 每次启动随机生成并打印在日志里 |

> ⚠️ **`AI_KEY_SECRET` 的不可逆性**：它用来加解密管理后台填写的 AI API Key。
> 平台一旦保存过任何 AI Key，**再改这个密钥就会导致所有已存的密文无法解密**，
> 只能回到「AI 配置中心」重新填写每个通道的 Key。
> 请生成后**立即备份**（密码管理器 / 纸质记录）。

## 二、快速部署（5 步）

### 步骤 1：生成密钥文件

```powershell
# Windows
powershell -ExecutionPolicy Bypass -File scripts\generate_secrets.ps1
```

```bash
# Linux / macOS（等价命令，用 openssl）
cd spring-backend
cat > .env <<EOF
JWT_SECRET=$(openssl rand -base64 48 | tr -d '\n=+/' | cut -c1-64)
AI_KEY_SECRET=$(openssl rand -base64 48 | tr -d '\n=+/' | cut -c1-64)
ADMIN_INIT_PASSWORD=$(openssl rand -base64 12 | tr -d '\n=+/')
APP_SECURITY_STRICT=true
SPRING_DATASOURCE_URL=jdbc:postgresql://localhost:5432/laos_agri
SPRING_DATASOURCE_USERNAME=postgres
SPRING_DATASOURCE_PASSWORD=你的数据库密码
AI_SERVICE_URL=http://localhost:8000
EOF
chmod 600 .env      # 只允许属主读写
```

脚本会生成 `spring-backend/.env` 并打印管理员密码，**请抄下来**。

`.env` 已被 `.gitignore` 排除，不会进版本库。

### 步骤 2：初始化数据库

```bash
psql -U postgres -c "CREATE DATABASE laos_agri;"
psql -U postgres -d laos_agri -f database/init.sql
psql -U postgres -d laos_agri -f database/v5_user_admin_ai_config.sql
psql -U postgres -d laos_agri -f database/seed_data_v1.sql          # 24 种病虫害
psql -U postgres -d laos_agri -f database/evaluation_record.sql
psql -U postgres -d laos_agri -f database/training_dataset.sql
```

> `v5` 脚本里有**破坏性语句**（修正手机号唯一性口径）：
> 它会 `DROP INDEX IF EXISTS core.uk_user_phone` 再建组合唯一索引。
> 若你的库是全新创建，无需关心；若是从旧版本升级，请先看该脚本第 2.1 节注释。

### 步骤 3：启动 AI 服务

```bash
cd ai-service
python3.11 -m venv .venv && source .venv/bin/activate   # 必须 3.11+（代码用了 PEP 604 语法）
pip install -r requirements.txt
cp .env.example .env        # AI 服务的 .env 只管它自己的默认通道
uvicorn main:app --host 0.0.0.0 --port 8000
```

> AI 服务的通道配置**以管理后台为准**：Spring 每次调用都会把当前生效通道的配置带过去，
> 所以 `ai-service/.env` 里的 AI 相关变量只作为兜底默认值。

### 步骤 4：启动业务后端

```bash
cd spring-backend
mvn -B -DskipTests package
java -jar target/agri-platform-1.0.0-SNAPSHOT.jar \
  --spring.profiles.active=prod \
  --app.security.strict=true
```

`.env` 会被**自动加载**（`DotEnvEnvironmentPostProcessor`），不需要 source 或 export。

启动日志会打印密钥自检结果：

```
密钥自检通过：JWT_SECRET / AI_KEY_SECRET / ADMIN_INIT_PASSWORD 均已正确配置
```

若看到下面这段，说明密钥有问题，**严格模式下会直接拒绝启动**：

```
启动被拒绝：生产模式(app.security.strict=true)下检测到密钥问题
   ✗ JWT_SECRET 未配置 —— 签发登录令牌的密钥...
```

### 步骤 5：构建并分发 APP

```bash
cd flutter_app
flutter build apk --release -t lib/main_vegetable.dart \
  --dart-define=API_BASE_URL=https://你的域名/api/v1

flutter build apk --release -t lib/main_fruit.dart \
  --dart-define=API_BASE_URL=https://你的域名/api/v1
```

## 三、启动参数速查

| 参数 / 变量 | 生产建议值 | 说明 |
|------------|-----------|------|
| `--spring.profiles.active` | `prod` | 用 PostgreSQL 配置 |
| `--app.security.strict` | `true` | 密钥不合格拒绝启动 |
| `APP_SECURITY_STRICT` | `true` | 同上（环境变量形式） |
| `OPS_TOKEN` | **留空** | 留空即关闭「本机重置密码」接口 |
| `APP_CORS_ALLOWED_ORIGINS` | 你的域名 | 如 `https://admin.example.com`；留空只放开本机 |
| `spring.thymeleaf.cache` | `true` | 生产关闭模板热加载以提升性能 |

## 四、上线后必做的 4 件事

1. **立即登录后台修改管理员密码**
   首次登录会有黄色横幅提醒，点「立即修改」。
   初始密码只应存在于 `.env` 与你的记录里。

2. **在「AI 配置中心」配置真实的 AI 通道**
   选通道 → 填 API Key → **先点「测试连接」** → 保存 → 「设为当前生效」。
   密钥会以 AES-256-GCM 加密入库，界面只显示脱敏串。

3. **备份 `AI_KEY_SECRET`**（最容易漏、后果最严重的一步）
   数据库备份 + `AI_KEY_SECRET` 才是完整可恢复的。

4. **验证三项健康检查**
   ```bash
   curl -s https://你的域名/actuator/health          # {"status":"UP"}
   curl -s -o /dev/null -w "%{http_code}" https://你的域名/admin/login    # 200
   curl -s -o /dev/null -w "%{http_code}" https://你的域名/api/v1/admin/ai/configs  # 401（未登录）
   ```

## 五、运维常用操作

| 操作 | 命令 |
|------|------|
| 查看生效的密钥来源 | 启动日志搜 `密钥自检` |
| 重置管理员密码（本机） | `scripts/reset_admin_password.ps1 -Password 新密码`（需 `OPS_TOKEN`） |
| 重置农户密码 | 后台「用户管理」→ 重置密码（无需脚本） |
| 切换 AI 通道 | 后台「AI 配置中心」→ 设为当前生效（**无需重启**） |
| 停用某用户 | 后台「用户管理」→ 停用（该用户所有设备立即退出） |
| 后台切换语言 | 右上角「中文 / ລາວ」 |
| 验证旧令牌已失效 | 换密钥后访问 `/api/v1/auth/me`，应返回 401 |

## 六、常见部署问题

| 现象 | 原因 | 处理 |
|------|------|------|
| 启动即失败，日志有「启动被拒绝」 | 密钥缺失/过弱 + 严格模式 | 按日志提示执行 `generate_secrets.ps1`，或补齐环境变量 |
| 启动日志有「密钥自检发现 N 项问题」但能起来 | `strict=false`（开发模式） | 生产务必加 `--app.security.strict=true` |
| `.env` 改了没生效 | 真实环境变量优先级高于 `.env` | 检查 shell 里是否已 `export` 了同名变量 |
| 密钥填了但仍提示未配置 | 变量名写错（如 `JWT_SECRET_KEY`） | 必须是 `JWT_SECRET`、`AI_KEY_SECRET`、`ADMIN_INIT_PASSWORD` |
| AI 识别报「AI识别服务不可用」 | AI 服务未启动或 Key 无效 | 后台「AI 配置中心」点「测试连接」看具体报错 |
| 换服务器后 AI Key 解不开 | `AI_KEY_SECRET` 与旧环境不一致 | 用原密钥；或回后台重填 Key |
| 后台样式错乱/中文乱码 | 模板缓存 + 编码 | 确认 `server.servlet.encoding` 为 UTF-8（默认已是） |
| APP 连不上 | 地址/防火墙 | 看 APP 启动日志 `[LaosAgri] spring=...`；放行端口 |

## 七、Linux 上用 systemd 托管（推荐）

```ini
# /etc/systemd/system/laos-agri.service
[Unit]
Description=Laos Agri Platform (Spring Boot)
After=network.target postgresql.service

[Service]
Type=simple
User=laosagri
WorkingDirectory=/opt/laos-agri/spring-backend
# .env 会被应用自动读取，无需 EnvironmentFile
ExecStart=/usr/bin/java -jar /opt/laos-agri/spring-backend/target/agri-platform-1.0.0-SNAPSHOT.jar \
          --spring.profiles.active=prod --app.security.strict=true
Restart=on-failure
RestartSec=10

[Install]
WantedBy=multi-user.target
```

```bash
sudo systemctl daemon-reload
sudo systemctl enable --now laos-agri
sudo journalctl -u laos-agri -f      # 看启动日志里的密钥自检结果
```

> 记得 `chmod 600 /opt/laos-agri/spring-backend/.env` 并确保 `laosagri` 用户可读。

## 八、安全检查清单（上线前逐项确认）

- [ ] `JWT_SECRET` 是 64 位随机值，不是示例值
- [ ] `AI_KEY_SECRET` 是 64 位随机值，**且已备份**
- [ ] `ADMIN_INIT_PASSWORD` 已改为强密码，且登录后已再次修改
- [ ] 启动参数含 `--app.security.strict=true`
- [ ] `OPS_TOKEN` 已留空（关闭本机重置接口）
- [ ] `APP_CORS_ALLOWED_ORIGINS` 已设为你自己的域名（未使用 `*`）
- [ ] `.env` 文件权限为 `600`，且**未被提交到版本库**（`git check-ignore spring-backend/.env`）
- [ ] HTTPS 已启用（令牌与密码都走明文 HTTP 会泄露）
- [ ] 数据库使用独立账号与强密码，未使用 `postgres/postgres`

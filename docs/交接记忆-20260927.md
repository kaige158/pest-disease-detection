## 0. 先读这三段（不读会踩坑）

1. **服务器上的项目路径是 `/opt/laos-cn-APP`（有 `s`）**，本地 Windows 是 `F:\lao-cn-APP`。两者名字不一样，照抄本地路径会导致所有命令失败。
2. **绝对不要用 PowerShell 的文本替换去改 UTF-8 文件**（`(Get-Content -Raw) -replace ... | Set-Content -Encoding utf8`）。它会把文件按 ANSI 重新编码，中文变乱码、`<` 之类的字符会被吃掉 —— 已经因此把后台「用户管理」页搞成过白屏。**编辑一律用 edit 工具**。
3. **AI 容器内存上限只有 700MB**。任何"对原图逐像素做 Python 循环"的代码都会把它打挂（`list(img.getdata())` 对 1200 万像素照片 ≈ 0.8GB）。见 `docs/故障复盘-20260927-拍照识别不可用.md`。逐像素统计只能在缩略图上做。

## 3. 常用操作手册（复制即用）

### 3.1 更新代码并重建服务

```bash
cd /opt/laos-cn-APP && git pull          # 服务器在海外，git 直连 GitHub 没问题
cd deploy
docker compose -f docker-compose.prod.yml build spring ai-service   # 改哪個 build 哪个
docker compose -f docker-compose.prod.yml up -d spring ai-service
sleep 30
docker compose -f docker-compose.prod.yml ps
```

### 3.2 看日志

```bash
docker logs laos_spring --tail 100
docker logs laos_ai --tail 100
docker logs laos_nginx --tail 50
# 只看关键行
docker logs laos_spring --tail 200 | grep -aE "AI 服务地址|下发 AI 通道|调用 AI|AI 识别"
```

### 3.3 端到端验证识别（最有用的一条命令）

```bash
IMG=$(find /opt/laos-cn-APP/raw_materials -iname '*.jpg' -o -iname '*.JPG' | head -1)
curl -s -X POST http://127.0.0.1/api/v1/recognition/identify \
  -F "image=@$IMG" -F "language=zh" -F "version=vegetable" | head -c 600; echo
```

### 3.4 验证 AI 助手（文本）

```bash
curl -s -X POST http://127.0.0.1/api/v1/assistant/chat -H "Content-Type: application/json" \
  -d '{"message":"番茄叶子发黄怎么办？","language":"zh","version":"vegetable"}' | head -c 400
```

### 3.5 查数据库

```bash
# 用容器自己的环境变量，避免猜用户名/库名
docker exec laos_pg sh -c 'psql -U "$POSTGRES_USER" -d "$POSTGRES_DB" -c "
  select id, provider, model, is_active from core.ai_provider_config order by id;"'

docker exec laos_pg sh -c 'psql -U "$POSTGRES_USER" -d "$POSTGRES_DB" -c "
  select task_id, image_url, status, top_confidence, created_at
  from core.diagnosis_record order by id desc limit 10;"'
```

### 3.6 上传的识别图片在哪（三个视角，同一个文件）

| 视角 | 路径 |
|---|---|
| 容器内 | `/data/uploads/recognition/<文件名>.jpg` |
| **服务器宿主机** | **`/opt/laos-cn-APP/deploy/data/uploads/recognition/`** |
| 公网 URL | `http://47.242.241.63/uploads/recognition/<文件名>.jpg` |
| 数据库里存的 | `core.diagnosis_record.image_url` = `/uploads/recognition/<文件名>.jpg`（相对路径） |

```bash
# 宿主机上列文件（按时间倒序）
ls -lht /opt/laos-cn-APP/deploy/data/uploads/recognition/ | head -20
# 占了多少空间
du -sh /opt/laos-cn-APP/deploy/data/uploads/
```

> 映射关系：`deploy/docker-compose.prod.yml` 里 `./data/uploads:/data/uploads`，
> Spring 的 `UPLOAD_DIR=/data/uploads`（`app.storage.upload-dir`），
> nginx `location /uploads/ { alias /data/uploads/; }`。
> 后台「AI审核中心」现在会**直接显示图片缩略图**（点开看大图）。

### 3.7 备份三件套（试用期结束前必须做，缺一不可）

```bash
mkdir -p /root/backup-$(date +%F) && cd /root/backup-$(date +%F)
docker exec laos_pg sh -c 'pg_dump -U "$POSTGRES_USER" -d "$POSTGRES_DB"' > db.sql
tar czf uploads.tar.gz -C /opt/laos-cn-APP/deploy/data uploads
cp /opt/laos-cn-APP/deploy/.env .env.backup      # 里面是 AI_KEY_SECRET 等主密钥
ls -lh
```

**⚠️ `.env` 里的 `AI_KEY_SECRET` 丢了，数据库里已加密的 API Key 就永久解不开了。** 数据库、uploads、`.env` 必须一起搬。

## 5. 环境与配置的坑

| 项 | 说明 |
|---|---|
| **AI 通道配置** | 唯一来源是数据库 `core.ai_provider_config`，由 Spring 随请求下发给 AI 服务（AI 服务不连库、不重启即可换模型） |
| 当前生效通道 | `id=2`，`provider=deepseek`，`model=deepseek-v4-flash-vision-exp`，已配 Key —— **实测能识别图片**，先别动 |
| 「测试连接」的局限 | 它只测**文本**接口。**测试通过 ≠ 能识别图片**（界面上已标注各通道是否支持图片） |
| `.env` 里的临时项 | `SPRING_JPA_HIBERNATE_DDL_AUTO=update`（掩盖实体与 SQL 的字段漂移）、`SERVER_ERROR_INCLUDE_MESSAGE=always`。**上线前要清掉**，并把缺失字段补进 SQL |
| 短信闸门 | `SMS_REQUIRE_CODE=false` / `SMS_EXPOSE_CODE=false`（老挝短信通道未采购，演示期关闭；代码路径与测试都已就绪） |
| 单管理员设计 | 全系统只允许一个 ADMIN；忘记密码的救援方式：设 `OPS_TOKEN` 后调 `http://127.0.0.1:8080/api/v1/ops/reset-password`，或直接改库里的 `password_hash` |
| 删除账号策略 | **只删账号与个人信息**，识别记录匿名保留、训练数据资产一字不动（这是硬约束，不要"顺手"把数据删了） |
| 演示环境 | demo profile 用 H2 内存库，重启即清空；生产走 PostgreSQL |
| Git | 远端 `https://github.com/kaige158/pest-disease-detection.git`（public）。**本地推送要挂代理**：`git -c http.proxy=http://127.0.0.1:7897 push`；服务器上 `git pull` 直连即可 |

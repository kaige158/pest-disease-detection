fix(db): 修正 v5 建库脚本的语句顺序 —— 唯一索引引用了尚未创建的列

现象
- 生产首次部署，postgres 初始化跑到 04-v5_user_admin_ai_config.sql 就中断
- core 下只有 11 张表：缺 phone_verification 与 audit_log
- 后端 ddl-auto=validate 因此反复重启（先是 ai_provider_config，修好权限后轮到这两张）

根因
- 脚本里 CREATE UNIQUE INDEX ... ON core."user"(country_code, phone)
  写在 ALTER TABLE core."user" ADD COLUMN country_code **之前**
- PostgreSQL 报 column "country_code" does not exist 并中断整个脚本，
  后面的两张建表语句全都没执行
- 之所以一直没暴露：该脚本此前只在 H2 上跑过，而 H2 的表由 JPA 自动创建

修复
- 把手机号唯一索引挪到 country_code 建列之后（2.5.1 小节）
- 并在该节开头写明顺序陷阱，避免以后再犯
